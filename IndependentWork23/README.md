# Самостійна робота №23
## Тема: Adapter + Facade + Proxy: кеш і ліміти (підготовка до екзамену)
## Контрольні питання

### 1. Поясніть патерн Adapter. Коли його слід використовувати?
**Adapter (Адаптер)** — це структурний патерн проєктування, який дозволяє об'єктам із несумісними інтерфейсами працювати разом. Він виступає в ролі "перекладача" або "перехідника" між клієнтським кодом та стороннім чи застарілим класом.

**Коли його слід використовувати:**
* **Інтеграція legacy-коду або сторонніх бібліотек:** Коли у вас є готовий клас (*Adaptee*), інтерфейс якого не відповідає вашому поточному коду (*Target*), а змінювати вихідний код цього стороннього класу не можна (або немає доступу).
* **Створення перевикористовуваного модуля:** Коли потрібно створити модуль, який має взаємодіяти з різними, заздалегідь невідомими джерелами даних, приводячи їхні специфічні інтерфейси до єдиного стандартного вигляду у вашій системі.

---

### 2. Поясніть патерн Facade. Як він спрощує роботу зі складними підсистемами?
**Facade (Фасад)** — це патерн, який надає простий, уніфікований інтерфейс до складної підсистеми (набору багатьох інструментів, класів, бібліотек чи API). Замість того, щоб змушувати клієнта розбиратися в десятках внутрішніх компонентів, Фасад приховує всю внутрішню «кухню» і виносить назовні лише кілька високорівневих методів.

**Як він спрощує роботу:**
* **Зменшує кількість зв'язків (Loose Coupling):** Клієнтський код залежить лише від одного класу-фасаду, а не від двадцяти внутрішніх класів підсистеми.
* **Інкапсулює порядок дій:** Фасад бере на себе менеджмент залежностей, правильну послідовність ініціалізації та викликів методів. Клієнту не потрібно знати, що для купівлі товару треба спочатку викликати `PaymentService.Verify()`, потім `Inventory.Lock()`, а в кінці `Sms.Send()`. Він просто викликає один метод фасаду — `OrderFacade.PlaceOrder()`.

### 3. Поясніть патерн Proxy. Наведіть приклади різних типів Proxy (Virtual, Protection, Logging).
**Proxy (Заступник / Проксі)** — це структурний патерн, який надає об'єкт-замінник замість реального цільового об'єкта. Проксі перехоплює всі виклики до оригінального об'єкта, дозволяючи виконувати додаткову логіку **до** або **після** того, як запит долетить до реального об'єкта. При цьому Проксі має *точно такий самий інтерфейс*, як і оригінальний об'єкт.

**Приклади різних типів Proxy:**
* **Virtual Proxy (Віртуальний проксі / Ледаче завантаження):** Використовується для економії ресурсів (RAM/CPU), коли створення реального об'єкта є дуже «важкою» операцією.
  * *Приклад:* Великий звіт або high-res зображення. Проксі створює порожню "заглушку", а реальний об'єкт викачує з бази даних чи мережі лише тоді, колі клієнт вперше викликає метод відображення даних на екрані.
* **Protection Proxy (Захисний / Контроль доступу):** Перевіряє права доступу клієнта перед делегуванням виклику реальному об'єкту.
  * *Приклад:* Система управління документами. Проксі перехоплює метод `DeleteDocument()`, перевіряє, чи має поточний користувач роль `Admin`, і якщо ні — викидає виняток, навіть не турбуючи сервіс видалення.
* **Logging Proxy (Логуючий проксі):** Зберігає історію запитів до реального об'єкта без втручання в його код.
  * *Приклад:* Логування запитів до бази даних. Проксі перехоплює виклик методу `ExecuteQuery()`, фіксує в лог-файлі час початку, параметри запиту, викликає реальну БД, а після повернення результату записує тривалість операції.

### 4. У чому полягає ключова відмінність між Adapter, Facade та Proxy?
Хоча всі три патерни є "обгортками" над іншими класами, вони мають абсолютно **різну архітектурну мету (намір)**:

| Патерн | Що робить з інтерфейсом? | Головна мета (Намір) | Хто з ним працює? |
| :--- | :--- | :--- | :--- |
| **Adapter** | **Змінює / трансформує** інтерфейс. | Забезпечити **сумісність** між двома різними інтерфейсами. | Клієнт, який очікує свій (новий) формат, але змушений працювати зі старим/стороннім класом. |
| **Facade** | **Спрощує** інтерфейс. | Сховати складність та надати **легкий доступ** до підсистеми. | Клієнт, якому ліньки (і не потрібно) розбиратися у внутрішній логіці та зв'язках підсистеми. |
| **Proxy** | Залишає інтерфейс **незмінним**. | **Контролювати доступ** до об'єкта (додавати кеш, лог, захист чи ліниву ініціалізацію). | Клієнт думає, що працює з реальним об'єктом, бо інтерфейси абсолютно ідентичні. |
