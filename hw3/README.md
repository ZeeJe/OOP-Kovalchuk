# Домашня робота №3. Принципи ISP та DIP
## Тема: Принципи розділення інтерфейсу та інверсії залежностей
# 1. Принцип розділення інтерфейсу (ISP)
Принцип розділення інтерфейсу стверджує, що жоден клієнт не повинен залежати від методів, які він не використовує. Замість одного великого інтерфейсу краще створити кілька спеціалізованих.

## Опис реалізації (Порушення ISP)
Уявімо інтерфейс для системи розумного будинку, де один інтерфейс змушує всі пристрої мати функції і світла, і сигналізації:

public interface ISmartDevice
{
    void TurnOnLight();
    void SetAlarm();
}
Якщо ми створюємо звичайну розумну лампу, вона буде змушена реалізувати метод SetAlarm(), який їй не потрібен.

## Рішення (Дотримання ISP)
Ми розділяємо функції на "вузькі" інтерфейси:

public interface ILight { void TurnOnLight(); }
public interface IAlarm { void SetAlarm(); }

public class SmartLamp : ILight 
{
    public void TurnOnLight() => Console.WriteLine("Світло увімкнено");
}
# 2. Принцип інверсії залежностей (DIP)
Принцип інверсії залежностей каже, що класи високого рівня не повинні залежати від конкретних класів низького рівня. Обидва мають залежати від абстракцій (інтерфейсів).

## Переваги застосування DIP через Dependency Injection (DI):
Гнучкість: Ми можемо легко замінити один сервіс іншим (наприклад, змінити відправку SMS на Email), не переписуючи основну логіку програми.

Масштабованість: Додавання нових функцій не потребує радикальних змін у існуючому коді.

Слабкий зв'язок: Компоненти системи стають незалежними, що полегшує їх підтримку.

# 3. Тестування та "вузькі" інтерфейси
Вузькі інтерфейси (ISP) роблять систему ідеальною для Unit-тестування та DI:

1. Легке створення Mock-об'єктів: Для тестування класу нам не потрібно створювати складну заглушку для величезного інтерфейсу. Ми створюємо Mock тільки для маленького інтерфейсу з 1-2 методами.

2. Чіткі залежності: Через конструктор класу (DI) ми передаємо тільки ті інтерфейси, які дійсно потрібні. Це робить код зрозумілим: одразу видно, що саме робить цей клас.

3. Менше побічних ефектів: Оскільки інтерфейс вузький, ми впевнені, що тест перевіряє саме ту частину логіки, яка нам потрібна, не зачіпаючи зайвого.

# Висновок
Принципи ISP та DIP є фундаментом для створення гнучких та тестованих систем. ISP звільняє класи від зайвих залежностей, роблячи інтерфейси "вузькими" та зрозумілими. У свою чергу, DIP дозволяє переорієнтувати архітектуру з конкретних деталей на абстракції. Поєднання цих принципів дозволяє розробнику змінювати логіку окремих модулів без ризику зламати всю систему, що є ключовим показником якісного коду.
